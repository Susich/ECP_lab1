## 3. Регламент формирования коммитов в Git

В репозитории строго соблюдается конвенция **Conventional Commits**:
- Каждый коммит представляет собой **одно логическое изменение** (атомарность).
- Сообщение коммита объясняет, *зачем* и *какой артефакт* был изменен, а не просто констатирует факт редактирования.
- Язык сообщений: русский (единообразно по всей истории).
- Запрещены односложные сообщения (`fix`, `update`, `правки`).

### Допустимые типы коммитов:
- `docs:` — добавление или изменение аналитической документации (`case_concept.md`, `review_log.md`, `README.md`).
- `feat:` — добавление функциональных артефактов и матриц (`RTM.md`, спецификации API).
- `refactor:` — реструктуризация разделов документации без изменения сути требований.
- `merge:` — фиксация слияния тематической ветки.

### Примеры допустимых коммитов:
```text
docs: разработка документа концепции и границ проекта (case_concept.md)
feat: добавлена матрица трассировки требований (RTM.md)
docs: добавлен отчет о внутреннем ревью документа концепции (review_log.md)
merge: слияние ветки feature/variant-03-concept после успешного ревью
```

## 4. Модель ветвления и процесс ревью (Git Flow)

Работа над документацией велась по командной модели с обязательным код-ревью:
1. От стабильной ветки `main` создана тематическая ветка `feature/variant-03-concept`.
2. Автор разработки (**Сапунков А. Р.**) зафиксировал документ концепции, матрицу трассировки и исследовательские материалы.
3. Ревьюер (**Блошкин Ю. В.**) провел перекрестную проверку, оформил замечания в `review_log.md` (в частности, добавлена обработка сценария с плательщиком-родителем, формат PDF/A и регламентный таймаут 14 дней).
4. После внесения правок выполнен `merge` ветки `feature/variant-03-concept` в ветку `main` с флагом `--no-ff` для сохранения графа истории.
5. Итоговое состояние репозитория зафиксировано релизным тегом `v1.0-concept-freeze`.

## 5. Проверка целостности и истории Git

Для проверки репозитория преподавателем:

```powershell
# 1. Просмотр полной истории коммитов с графом ветвления и слияния
git log --graph --oneline --decorate --all

# 2. Просмотр информации о релизном теге
git show v1.0-concept-freeze

# 3. Проверка текущей ветки и статуса рабочей копии
git status
```
